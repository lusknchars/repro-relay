# Scheduled Hermes programs

Open **Agents → Programs → New program**. Pick Smoke check, Regression review or Test triage, choose an existing repository work record, then set the first run, repeat interval and time limit. Automatic execution is the default. Saving authorizes that routine against the selected record's current build, reproduction conditions, evidence and team workflow. The administrator can instead require a start decision for each occurrence.

Programs and occurrence history live in PostgreSQL. The existing local API automation worker checks due programs every two seconds, independently of the open page. The Relay service and configured Hermes runtime must remain running. Closing the window does not schedule work in macOS itself, and Relay cannot wake a sleeping computer. Daily and weekly mean fixed 24-hour and 7-day intervals from the saved UTC instant. The UI displays local times and its timezone; daylight-saving changes can shift the displayed hour. There is no Google Calendar dependency.

A missed interval creates at most one outstanding occurrence per program, and advances the next time beyond now. Outstanding approvals, blocked runs and active runs prevent a backlog. Programs queue behind the workspace's existing single active investigation. Pausing fences future admission; it does not cancel an already admitted run. Use Work's existing stop control for that. Resume retains pending work. Review / reschedule replaces the schedule, cancels outstanding unadmitted occurrences, and reviews the current source context again.

An occurrence and its run share a durable request identity. Admission and its run link commit together, and concurrent workers cannot create duplicate runs. Each run freezes the selected protocol and the existing investigator context. Changed source context, missing build, unavailable runtime and exhausted case history become explicit blocks. Retry retains the occurrence identity. A source-context mismatch requires Review / reschedule rather than repeated retries. The same administrator/member access rules as other execution controls apply; guest workspaces cannot create programs.

Routines use the connected investigator's configured test tools and approved environment. They do not install dependencies, grant shell permissions, edit code, send messages, publish memory, or create independent fix verification. Smoke/regression routines ask for actual steps, command output and evidence where tools permit them. Triage classifies available evidence. A successful agent completion is not a passed test. The existing 30–600 second limit is cooperative, not a hard token or dollar budget. Costs remain attached to the actual run in Usage.

The workspace supports 50 saved programs. Each case retains its existing 100-run limit. The page shows the latest 100 occurrences with links to their original work records, even if a program is later edited. Persisted history is not deleted when pausing or editing.

Validation uses PostgreSQL tests for concurrent admission, source changes, pause/resume versions, manual approval, scope tampering, unavailable runtime and rescheduling. Browser tests cover real program persistence, automatic admission through a controlled HTTP fixture, linked results, draft preservation and narrow layouts. The fixture does not spend model credits or execute repository commands.
