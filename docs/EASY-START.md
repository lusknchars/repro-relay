# Start Relay with Docker

The packaged installation needs Docker Desktop or a local Docker Engine with Compose. It starts a private workspace without a login. It does not require a provider subscription to open existing work, add todos, or review evidence.

```sh
curl -fsSL https://raw.githubusercontent.com/lusknchars/repro-relay/main/install.sh | sh
```

The installer downloads this repository into `~/.local/share/repro-relay`. It never replaces an existing unmanaged directory. Repeating it reuses your installation. To inspect the installer first, download `install.sh`, read it, and run `sh install.sh`. A source download also includes `Start Relay.command` for macOS and `start.sh` for Terminal.

1. Check that Docker is running locally.
2. Download the published package for your processor. If unavailable, build the included source inside Docker.
3. Start PostgreSQL and apply the application's database migrations.
4. Wait for both services to become healthy, then open `http://127.0.0.1:8178`.
5. Create or reuse your local administrator session automatically.

The first source build can take several minutes. Subsequent starts reuse Docker's cache. A failed start leaves data in place and shows a command to inspect logs. The installer does not report readiness until Compose's health checks pass.

## Everyday controls

```sh
cd ~/.local/share/repro-relay
./start.sh          # Start and open
./start.sh status   # Inspect service health
./start.sh logs     # Last 100 application log lines
./start.sh stop     # Stop both services, keep data
```

Containers restart when Docker restarts unless you deliberately stopped them. `RELAY_NO_OPEN=1 ./start.sh` keeps the browser closed. `RELAY_INSTALL_DIR=/absolute/path` selects an installation directory, but installations use the same `relay-local` Compose project by default; this is not a multi-instance installer.

The app is bound to host loopback. The database has no published port. `relay-local_database` retains database records and `relay-local_settings` retains private integration settings. These are separate from a contributor's existing `repro-relay_relay-data` volume. Docker volumes are persistence, not backups.

If port 8178 is already occupied, stop your existing Relay service before starting the package. The installer never kills another process or adopts another database. Keep the `127.0.0.1` port binding: this passwordless workspace must not be exposed on a public address. Remote Docker contexts are rejected by the launcher. The backend's container listener also requires explicit local-mode opt-in inside Docker and retains existing origin checks.

## Updates

The first successful image download saves its immutable digest in `.relay-image`. A successful source build saves `source` there instead. Reopening preserves that choice, so normal startup does not silently move you onto a newer image or apply an unexpected release's migrations.

After reviewing an update and backing up your volumes, remove `.relay-image` and run `./start.sh` to download the current package. Deleting the digest does not delete data. A source-built installation retains its downloaded snapshot; use an updated checkout and `RELAY_BUILD=1 ./start.sh` to build a new revision against the same project. Database migrations may prevent rollback to older versions, so restore a matching backup when rolling back.

Maintainers can also set `RELAY_IMAGE` to a specific trusted image digest. This bypasses discovery and does not save a new default. `RELAY_BUILD=1` forces the source build when no explicit image override is set.

## Connections and desktop

This package includes the frontend, Rust API, PostgreSQL, Python and Relay's integration scripts. It does not contain a running Hermes gateway, paid model credentials, browser automation worker, or authenticated external accounts. Settings should report those connections as unavailable until configured. No sample agent activity or spend is generated by installation.

The container has its own filesystem. It cannot read your Mac's repositories, invoke your host's Pi binary, open Plow Latch on the host, or use host keychain credentials by itself. Use the source/native setup for host-controlled workflows today, or connect a separately configured runtime. Do not mount your entire home directory or Docker socket into Relay. Google installed-app OAuth callback routing in this package remains unverified.

This is the browser application on your computer. The native macOS application is still a development build requiring the source toolchain; a signed, notarized app that owns its service lifecycle is not yet shipped. Teammates on other computers require [shared HTTPS access](ACCOUNTS-AND-TEAM.md). The existing hosted guest beta is a separate, limited mode and is not a shared administrator workspace.

## Package publishing

The `Packaged local app` workflow builds native Linux ARM64 and AMD64 images, tests each against a disposable database, then publishes the architecture tags and combined `ghcr.io/lusknchars/repro-relay:main` manifest. The smoke test exercises real no-login access, foreign host/origin rejection, owner reuse and persistence after both containers are recreated. It makes no model requests.

On the first GHCR publication, the repository owner may need to make the package public in GitHub's package settings. Verify an unauthenticated pull before announcing the prebuilt path. Until that succeeds, startup falls back to a source build without asking users to log into a registry. Forks must update the installer download URL, package reference and image source label before distributing their installer.

The setup uses Docker's [service health checks and dependencies](https://docs.docker.com/reference/compose-file/services/) and GitHub's [container publishing workflow](https://docs.github.com/en/actions/tutorials/publish-packages/publish-docker-images).
